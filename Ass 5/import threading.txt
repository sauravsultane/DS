Logic of This Code
This code implements the Token Ring Mutual Exclusion algorithm.
The main logic is:

Only the process holding the token can enter the critical section.

After completing its work, the token is passed to the next process in a circular order.

Problem This Algorithm Solves
In distributed systems:


many processes may try to use the same shared resource,


if multiple processes access it together, conflicts occur.


Example:


shared file,


printer,


database,


memory.


So only one process should access the resource at a time.
This is called:
Mutual Exclusion

Main Idea of Token Ring
A special object called token circulates among processes.
Rule:
Process with token → can enter critical sectionProcess without token → must wait

Ring Structure
Processes form a circular ring.
Example:
0 → 1 → 2 → 3 → 4 → 0
The token continuously moves in this order.

Main Logic Step-by-Step

Step 1: Create Processes
ring = TokenRing(num_processes=5)
Creates 5 processes.

Step 2: Give Token to Process 0
self.current_holder = 0
Initially:


Process 0 owns token.



Step 3: All Processes Keep Checking
Each process continuously checks:
if self.current_holder == process_id and self.token:
Meaning:
"Do I currently have the token?"

Step 4: Enter Critical Section
If process has token:
self.critical_section(process_id)
Process enters critical section.
Only one process can enter because:


only one token exists.



Example
Process 0 ENTERING critical section
Other processes wait.

Step 5: Simulate Work
time.sleep(random.uniform(1,2))
Simulates process using shared resource.

Step 6: Exit Critical Section
Process 0 EXITING critical section
Process finishes work.

Step 7: Pass Token to Next Process
self.current_holder = (process_id + 1) % self.num_processes
Moves token to next process.

Example
If current process:
Process 2
Then:
(2 + 1) % 5 = 3
Token goes to Process 3.

Circular Ring Logic
If current process is last process:
Process 4
Then:
(4 + 1) % 5 = 0
Token returns to Process 0.
This creates circular ring movement.

Step 8: Repeat Forever
Processes continuously:


wait for token,


use critical section,


pass token.



Important Logic Used

1. Only One Token Exists
self.token = True
Ensures:


only one process enters critical section.



2. Lock Prevents Race Conditions
with self.lock:
Prevents multiple threads from modifying token data simultaneously.

3. Threads Simulate Processes
threading.Thread()
Each thread acts like a separate process.

Overall Working Flow
Token starts at Process 0        ↓Process 0 enters critical section        ↓Process 0 exits        ↓Token moves to Process 1        ↓Process 1 enters critical section        ↓Token moves to Process 2        ↓Repeat continuously

Notice:

Why Token Ring Is Useful
Advantages:


avoids conflicts,
